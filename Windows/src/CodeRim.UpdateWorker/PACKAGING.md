# Windows update packaging contract

The default `Windows/Scripts/package.ps1` invocation still produces an unsigned portable ZIP. It includes an inert update worker: without the compiled publisher pin and signed manifest, the worker returns `SigningNotConfigured`. Existing manual ZIP/install.ps1 behavior remains available for portable and legacy installations. An unsigned installer refuses to overwrite a managed signed receipt. No certificate is created or added to an OS trust store.

Signed managed installations are an explicit opt-in release configuration. Run the package script with `SigningMode Required`, an existing CurrentUser/My code-signing certificate thumbprint, and the exact lowercase SHA-256 of its DER SubjectPublicKeyInfo. The signing branch requires PowerShell 7 on Windows, an explicit validly signed Windows SDK signtool.exe, and an HTTPS RFC3161 timestamp server. SignTool uses SHA-256 for both the file digest and RFC3161 timestamp; the PowerShell signature API is not used for HTTPS timestamping. These are build inputs, never runtime environment trust overrides. A missing, mismatched, invalid, or untimestamped signing result stops packaging; it does not fall back to unsigned output.

The pipeline publishes app and CLI, switches the packaged install.ps1 to the signed branch, and signs the final app/CLI/PowerShell bytes using SHA-256. The Python standard-library inventory generator produces deterministic bounded manifest JSON plus neutral RT_RCDATA (type 10, id 21001, language 0). The manifest excludes the worker to avoid a circular self-hash. It is compiled into the worker's PE resource, then the worker is signed. At runtime the independently verified worker's complete signed-file hash and size are appended to the authenticated manifest. The final archive digest remains transport integrity, not publisher authentication.

The initial signed install is explicitly launched by the user. Its script requires valid installer/worker Authenticode signatures with identical signer certificate bytes. The worker additionally verifies its compiled publisher SPKI pin and signed payload, copies itself into the protected launcher area, and performs an authenticated initial binary transaction. It rejects an existing unmanaged/portable installation instead of taking ownership of unknown files. Shortcuts and optional CLI PATH setup happen in the installer only after a committed binary result; the transaction engine never changes settings, credentials, profiles, PATH, or the registry.

For updates, Information checks release metadata and downloads an exact asset with U1 limits and SHA-256. The application verifies the bytes at its own executable path against the compiled publisher pin and retains that read lease while starting its early bootstrap. The bootstrap runs before settings/vault/companion/single-instance work, authenticates the installed helper, and copies that helper into a private GUID launcher beneath the fixed per-user update root. A supervised child verifies and stages the release before the UI offers restart. The confirmation/acknowledgement handshake then waits for the exact original PID and process start time to exit. Cancel, navigation and window closure withdraw consent before handoff; the helper keeps observing that withdrawal during the parent wait. The supervisor also verifies and holds its own image before each child re-execution. A second supervised child reauthenticates the retained old/new identities and executes the transaction. Legacy/unsigned/portable builds retain the manual download path.

The initial in-process self-signature check has a 30-second observation deadline and at most one pending call; cancellation disposes any late verified lease. Windows native trust APIs cannot be forcibly interrupted in that UI process, so this is not a hard native-call termination guarantee. All validation/transaction children use an explicit protected `DOTNET_BUNDLE_EXTRACT_BASE_DIR` before managed startup and a minimal environment without credentials/cookies. Their job containment, two-minute child watchdog and supervision deadline bound network or filesystem stalls. The detached handoff supervisor has an eight-minute outer watchdog covering verification plus bounded user/parent waits. A timeout or unclassified exit requires recovery; it never proves rollback. The normal verified application restart uses `CreateEnvironmentBlock(current token, inherit=false)` to restore ordinary user/machine environment settings; that block is never sent to the update child or written to disk.

Recovery reauthenticates the signed old/new payloads and checks the transaction journal's exact manifest pair under the install commit lock. The UI's recovery action requires a second explicit quit acknowledgement. If a first installation is interrupted and no application can start, rerun the same signed package installer with `-RecoverOperationId OPERATION_ID`. The installer authenticates its worker and creates a new protected launcher for `recover-install`, which reauthenticates the preserved signed manifest before touching the journal. For an interrupted update without a working application, the retained authenticated helper supports `recover OPERATION_ID` from its protected launcher capsule. Results distinguish committed, committed with cleanup pending, rollback, and unclassified/recovery-required states. Completed update and first-install payload capsules move into a separate cleanup area before verified ownership cleanup. A rejected pre-commit preparation removes only files created by that invocation whose identities and hashes still match; a fully prepared but declined/cancelled/timed-out parent handoff removes the exact temporary ownership set without reporting a rollback. Unknown or changed files, interrupted transaction evidence, and unclassifiable partial writes remain preserved for recovery/manual review. Launcher executables and result receipts are retained for diagnosis and may require bounded retention work in a future release.

Current validation does **not** establish that CodeRim has a production signing certificate, that a signed CodeRim package was installed, or that this complete flow ran on native Windows. Synthetic manifests/PE parser fixtures do not authorize installation. Public Microsoft-signed inert PE checks establish only the WinVerifyTrust/SPKI primitive. A release must independently verify the actual signed resource, publisher pin, timestamp/chain behavior, x64/ARM64 native bootstrap/extraction, first installation, update/rollback, UI shutdown/relaunch, and installer PATH/shortcut behavior before describing signed automatic updating as deployed.
