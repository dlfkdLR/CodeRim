# CodeRim for Windows 2.1.16

The first Windows release that is no longer labelled a preview. It brings the provider sign-in work from macOS 2.1.15 to Windows, fixes what a full provider and connection audit found, and adds a Microsoft Store package. x64 and ARM64 MSI installers; macOS is unchanged at 2.1.15.

## Adding providers

- Adding a provider connects it in the same step. GitHub Copilot signs in with a short GitHub code and Antigravity with Google, without their command-line tools. GLM and Ollama take a pasted key, and website sign-ins explain how to import the browser session.
- Kiro signs in with `kiro-cli login`; JetBrains AI explains the IDE step and connects when the IDE writes its quota. Grok, Kiro, Codex, Cursor, OpenCode, Gemini CLI and Google Cloud open their install page when the command is missing, instead of an empty terminal.
- Sign-in terminals show the steps to follow in yellow and wait for Enter, then say whether the command finished. They run npm-installed tools even under the default PowerShell script policy, and find a tool installed after CodeRim started.
- Gemini CLI set to an API key says so and shows the `/auth` steps, instead of waiting ten minutes.
- Providers that need a key show **Get a key** until they connect, and saving the key connects a provider that was waiting for it. Cancel during the first sign-in removes a just-added provider.
- Wayfinder without a running gateway asks you to start it rather than reporting an error. The Claude Code page labels its on/off switch.

## iPhone connection

- A paired computer stays connected for as long as it is used. Earlier builds stopped sharing a year after pairing even though the relay had extended the connection.
- Restarting or updating CodeRim keeps the connection.

## Microsoft Store

A Store package (MSIX, x64 and ARM64) is built and installation-tested in CI. Microsoft signs Store packages, which removes the "unknown publisher" and Smart App Control blocks at no cost. Inside the Store package the Store keeps CodeRim up to date, `coderim` comes from an execution alias, and Launch at Login uses the package. The listing goes live once it passes Microsoft certification; the MSI below remains available.

## Verification

Windows: 4,496 core tests, including a provider matrix that runs every provider reader through 21 connection outcomes (refused or expired credentials, rate limits, server errors, no network, DNS and TLS failures, timeouts, unreadable and empty answers, login redirects) and every provider through seven add-and-sign-in flows. Native UI, installer lifecycle, rollback and Store-package installation run on x64 and ARM64 in [Windows CI](https://github.com/dlfkdLR/CodeRim/actions/workflows/windows.yml). Synthetic checks do not replace live accounts for each of the 70 services.
