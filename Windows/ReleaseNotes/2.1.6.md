# CodeRim 2.1.6 for Windows

This Windows update aligns the edge notch and Settings/Usage views with the macOS design. It fixes clipped rings, visible native scrollbars, stock tooltip/hover chrome, missing logo details, and account navigation. Hover dismissal, explicit pinning, refresh focus, all four screen edges and three sizes now share the intended interaction model.

The Windows source now has a connection route for each of the 70 catalog providers. New native readers cover Google OAuth/ADC, Kiro, Augment, Antigravity, Windsurf, OpenCode Zen, AWS profiles and signed cloud billing. Provider percentages, tokens, requests, points, credits and currency retain their original meaning. Expired authentication clears old quotas, and account/profile changes do not reuse another account's readings.

Codex/Claude local history, account verification/rollback, the Claude status-line bridge, usage navigation, saved credentials, update checks and the companion CLI have also been repaired. Windows Widgets are excluded.

## Install

Choose the x64 or ARM64 ZIP and verify it against SHA256SUMS-windows.txt. Close CodeRim, extract it and run install.ps1 for a per-user installation, or run CodeRim.exe from a permanent folder. Binaries are self-contained and unsigned; installation does not require administrator access. Settings and local history remain in the existing data directory.

This release contains Windows packages. The current macOS package remains [CodeRim 2.1.5](https://github.com/dlfkdLR/CodeRim/releases/tag/v2.1.5), with its existing Sparkle and Homebrew channels.

## Verification and limits

The core suite has 268 passing synthetic tests. Windows CI builds and packages x64/ARM64, executes the x64 WPF smoke checks, captures the actual WPF views, tests the Claude bridge and CLI, and verifies the per-user installation. Independent synthetic protocol reviews covered the newly ported readers.

Live authentication across all 70 providers, ARM64 execution, physical mixed-DPI monitors and every macOS login strategy have not been verified. Browser cookies require manual entry; remaining native/PTY login routes, provider activity monitors and in-place automatic updates are still outside this preview's implemented parity. See the [Windows capability guide](https://github.com/dlfkdLR/CodeRim/blob/main/Documentation/WINDOWS.md).

The separate development harness did not approve this run: its frozen verification-input checks reject changed tests/workflows, and the initial contract lacks provenance registrations for the modified logo assets. No harness ACCEPT or operator attestation is claimed. Direct test results and the independent reviews are recorded separately.
