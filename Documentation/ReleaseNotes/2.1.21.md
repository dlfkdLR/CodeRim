# CodeRim 2.1.21

A macOS-only release: it fixes Codex account switching after the Codex desktop app's update and adds a beta time-left estimate to the notch. Windows stays at 2.1.20.

## Codex accounts

- Switching, saving and adding Codex accounts no longer fails with "A verified Codex installation could not be used" after the Codex desktop app (0.163) moved its bundled CLI into a nested `codex-cli/CodexCLI.app` and began running that binary twice, as `app-server` and `exec-server`. Both the old and the new layout are recognised, and the app-server is picked by how it was started.

## Time left (beta)

- Hovering a working Claude, Codex or OpenCode session in the notch shows a typical range for how long is left (with the long tail underneath), when it should finish, and a bar that fills left to right. It is a prediction from how long your earlier turns took, shown as a range because turn lengths vary too much for one number, and it learns as you work. On this Mac's own history an 80% range held about 80% of the time; a single figure would not have.
- The clock and bar stop while a session waits for you, the estimate widens when you add an instruction mid-turn (Claude), and a turn that outlasts everything on record says "running long" instead of guessing.
- Past turn lengths are read from the agents' own logs on launch. Only durations and the folder name are kept, in `~/Library/Application Support/CodeRim/TurnHistory.json`.
- OpenCode sessions now appear in the notch's activity list, with the compaction state OpenCode records.
- Settings ▸ Notch ▸ Time Left: an opt-in toggle that installs two small Claude Code hooks (`PreCompact`/`PostCompact`) so the notch can say "compacting" while it happens. It backs up `~/.claude/settings.json` once, touches only its own entries, refuses a file it cannot parse, and removes them when switched off.

## Verification

macOS: 3,100+ tests in CI, including the layout and argument-parsing cases for the Codex fix. The read-only probe of the installed Codex desktop app passed on the development Mac. The hover bar was verified by unit tests and a rendered image, not yet by hand in the running app.
