# CodeRim 2.1.20

CodeRim 2.1.20 brings macOS up to date with the Windows 2.1.16–2.1.19 work and fixes the data, account and connection problems a full audit found on macOS, Windows and the iPhone relay. Universal macOS app and Windows x64/ARM64 installers.

## Usage numbers

- A token log whose counters each grow, but not consistently (cached input growing faster than input), no longer fails the refresh again and again on macOS or silently drops usage on Windows. The certain part is counted and the period is marked partial; Windows remembers the correction with the stored history.
- Today, this week and this month are judged by the sessions seen in them. An old session that could only be read partly marks **Local History** ("This total may be low") instead of every current period. Partial readings on Windows age into stale ones like complete readings.
- Windows stops re-saving and re-reading its whole history when no log changed, and a refresh dropped by an account switch is read again next time.

## Accounts

- A usage answer for the account signed in when the request started is not shown for the account signed in now: CodeRim compares the account before and after each read and reads again after a switch. Remembered readings, rate-limit waits and 80%/100% alerts belong to one account, so a switch starts each of them fresh.
- An alert for an unusually large usage figure can no longer close the app on macOS.

## Providers

- Reading providers side by side: one slow service no longer delays the others.
- A browser whose data cannot be read is skipped and the next browser is tried (Factory, MiniMax).
- The iPhone task list and the notch follow `CLAUDE_CONFIG_DIR` like usage does.

## iPhone connection

- Answers that arrive late on the iPhone can no longer bring back an earlier screen or older numbers, including after a filter change. Island updates for one account no longer wait for another account's.
- A computer whose sign-in has expired no longer takes one of the 16 places. The iPhone stays connected for as long as it is used.
- Windows: a relay or proxy that stops in the middle of an answer can no longer leave pairing, sharing or disconnect waiting forever.

## Also on macOS since 2.1.15

Provider sign-in on add without command-line tools (GitHub device code, Google sign-in for Antigravity, keys, browser sessions), Kiro and JetBrains AI sign-in, clearer provider errors, settings panes no longer covered by a scroller, and the Information page without the Data scope and Privacy rows.

## Verification

macOS: 3,099 tests plus 1,901 provider-matrix cases. Windows: 4,510 core tests, native UI and installer checks in CI. Relay: 52 tests. Live accounts and Apple push delivery were not exercised.
