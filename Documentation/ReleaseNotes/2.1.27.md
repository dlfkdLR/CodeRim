# CodeRim 2.1.27

A macOS-only release. Windows stays at 2.1.20.

## Another account's limits

- When two or more Codex accounts are saved, the Limits view shows an account menu at the top, in Settings and in the menu-bar popover. Choosing another account shows that account's limits and nothing else changes: the signed-in account, the Codex app and the saved logins stay as they are. Refresh reads the account you chose. Choosing the signed-in account goes back to the usual limits.
- The limits are read by starting a separate `codex app-server` with a copy of the saved login in a private temporary folder, which is deleted afterwards. If that read renews the login, the saved copy would stop working, so the renewed login is kept: saved straight away, or held and used for the next read and saved at the next chance when another account operation is running, and kept even when the read itself fails. A login that was replaced by signing in again is never overwritten by a waiting one.
- Claude is left out: its limits are only available for the signed-in account.

## Usage screen

- A model table (sessions, share, tokens), a top-projects table with each project's main model, and one table style for sessions, projects and models.
- A session opens into Tokens, Activity (start, duration, cache hit, sub-agents, images) and Models panels. Selecting a day in the chart lists that day's tokens by model.

## Verification

macOS: full local test suite with 0 failures, run with warnings as errors as CI does, including five tests of the renewed-login handling against synthetic accounts. The Usage screen was rendered offscreen at two widths in light and dark and read. Reading a second real account's limits has not been exercised against a live account; if it shows "Account limits unavailable", the signed-in account is unaffected.
