# 계정 저장과 전환

[English](ACCOUNTS.md) · **한국어**

## macOS 지원 구성

노치 계정 버튼, **Settings → Usage → Switch**, 제공업체 **Manage Accounts**를 사용합니다. Codex·Claude는 각각 최대 12개 구독 계정을 별도의 비동기화 로그인 Keychain 저장소에 보관합니다. 전환은 수동 확인이며 한도가 부족해도 자동 전환하지 않습니다. 저장한 복사본을 제거해도 원래 도구에서 로그아웃하거나 로그를 지우지 않습니다.

Codex는 `/Applications/Codex.app`·`/Applications/ChatGPT.app`의 공급자 서명된 데스크톱, 기본 `~/.codex`, 파일 기반의 완전한 ChatGPT 인증이 필요합니다. 등록·전환 시작 시 지원 데스크톱이 실행 중이어야 합니다. `CODEX_HOME`·HOME 대체 경로를 포함한 실제 홈을 검사합니다. 사용자 지정 홈, keyring·auto 저장, API 키, 외부 관리 토큰, 충돌 정책, 검사 불가 데스크톱은 활성 로그인 교체 전에 작업을 중단합니다. 이메일만으로 계정을 식별하지 않습니다. 같은 이메일도 workspace·subject가 다르면 다른 계정입니다.

## Codex 절차

1. **Save Current Account**는 현재 완전한 로그인을 전용 저장소에 보관합니다.
2. **Add Account**는 소유자 전용 임시 홈(`0700`)에서 검증한 번들 Codex CLI를 실행합니다. 브라우저 로그인은 활성 로그인을 교체하지 않습니다. Cancel은 소유한 자식만 종료하고 종료를 기다린 뒤 정리합니다. 충돌 시 시스템 정리 전까지 개인 임시 폴더가 남을 수 있습니다.
3. Switch 전에 떠나는 계정의 최신 로그인을 보관하고 정상 데스크톱 종료를 요청하며 지원 클라이언트를 검사합니다. 강제 종료하지 않습니다. `~/.codex/auth.json`을 잡고 있는 활성 클라이언트는 교체를 막고, 식별한 생존 클라이언트의 열린 파일을 검사할 수 없으면 검증 오류를 반환합니다. 파일을 놓은 유휴 클라이언트는 자동으로 막지 않습니다.
4. 소유자 전용 잠금으로 작업을 직렬화합니다. 원본 스냅샷과 현재 바이트를 비교한 뒤 개인 `0600` 임시 파일을 원자적으로 게시합니다. 로그인이 없으면 기존 파일을 덮어쓰지 않는 방식으로 게시해 동시 로그인에 우선권을 줍니다. 잘못되거나 안전하지 않은 파일을 없는 파일로 처리하지 않습니다.
5. 공식 데스크톱을 다시 엽니다. 번들 공식 CLI로 `refreshToken: false`의 `account/read`를 읽고 ChatGPT 이메일과 공유 파일의 전체 workspace·subject를 확인합니다. 기존 CLI는 자격 증명을 메모리에 유지할 수 있으므로 수동 재시작합니다. 로컬 확인은 원격 인증 증명이 아닙니다.
6. 기록 후 계정 확인이 실패하면 미검증 결과를 표시하고 현재 계정을 다시 읽습니다. 자동 rollback으로 동시 로그인·갱신을 덮어쓰지 않습니다. 공식 데스크톱이 갱신을 소유하며 저장한 자격 증명 복사본을 일회성 프로세스에서 갱신하지 않습니다.

## Claude 계정

기본 macOS 구독 OAuth Keychain 기록과 `~/.claude.json` 프로필을 지원합니다. 사용자 지정 `CLAUDE_CONFIG_DIR`, 관리형·API 키 인증, Keychain 외 자격 증명은 Claude Code가 관리합니다.

추가는 개인 임시 설정과 별도 Keychain 서비스에서 `claude auth login --claudeai`를 사용합니다. 시작 전에 명시적 로그아웃 상태를 요구하고 완료 후 임시 항목을 제거합니다. Cancel은 도우미만 중지합니다. 전환은 확인과 기존 Claude 세션 종료가 필요하며 떠나는 로그인을 보관하고 OAuth·프로필 계정 정보만 교체해 무관한 설정을 유지합니다.

자격 증명·원자 프로필 기록 전에 동시 변경을 재확인합니다. 프로필 교체가 실패하면 이번 작업이 기록한 자격 증명만 rollback합니다. 전환 후 `claude auth status`의 방식·이메일·조직·저장한 전체 ID를 확인하고 새 CLI 세션을 시작합니다. 만료·철회된 로그인은 공식 재로그인이 필요할 수 있습니다. 기존 세션은 강제 종료하지 않습니다.

## 상태·개인정보·검증

계정 변경은 한도·프로필 스냅샷을 무효화하고 generation·ID 검사로 이전 계정 응답을 버립니다. 로컬 히스토리는 계정에 관계없이 컴퓨터별 원장입니다. 자격 증명은 사용량 테이블·내보낸 스냅샷·로그·UI에 들어가지 않습니다. ad-hoc 업데이트는 Keychain 권한을 다시 요청할 수 있으며 접근 보호를 유지합니다.

합성 테스트는 임시 홈, 모의 데스크톱·CLI, 합성 저장소 항목을 사용합니다. 저장·추가·취소·전환·제거, 누락·위험 로그인, 활성 클라이언트, 오래된 결과, 동시 로그인, rollback, 프로필 보존을 검사합니다. 네이티브 렌더는 비어 있음·계정 있음·긴 ID·오류·작업 중 상태, footer, 두 크기·테마를 확인합니다. 실제 OAuth, 키보드·VoiceOver 순서, Keychain 권한, 서버 인증을 증명하지 않습니다. 자동 테스트로 개발자의 활성 로그인을 바꾸지 않습니다.

```sh
swift test --filter CodexAccount
swift test --filter ClaudeAccount
swift test --filter AccountUsageLayoutTests
```

Windows는 별도 DPAPI 저장소와 트랜잭션을 사용하므로 macOS Keychain 가정을 적용하지 않습니다. [Windows](WINDOWS.ko.md) · [개인정보](PRIVACY.ko.md).
